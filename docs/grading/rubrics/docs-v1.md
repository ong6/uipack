# Documentation and article rubric, version 1

Frozen on 2026-11-06. A change to any line is version 2 in a new file; this file never changes.
Score each page 1 to 10 per criterion against the descriptions of 3, 6 and 9, citing a screenshot
and a region (or quoted words) for every score. A severe flaw caps a criterion at 4. The overall
score is your judgement, not an average. Use the same rubric for the reference page.

| Score | Means |
| --- | --- |
| 9 | A top professional documentation team or writer would publish it unchanged |
| 6 | Correct and readable, but a reader has to work to find or trust things |
| 3 | A reader would give up or be misled |

## Criteria

### D1 Answer first

Definition: the opening says what the page gives the reader and the main answer or outcome, before
background.

- 3: The opening is history, marketing or a definition the reader did not ask for.
- 6: The purpose is stated, but the answer arrives after a screen of context.
- 9: The first two sentences state the outcome and who it is for; the rest supports them.

Check: quote the first two sentences. Do they contain the page's main answer? No scores 5 or less.

### D2 Scannable structure

Definition: headings, lists, tables and code blocks let a reader find their part without reading
everything.

- 3: Long undivided prose, or headings that do not describe their section.
- 6: Sensible headings; some sections bury steps or values in paragraphs.
- 9: Every heading is a task or a question; steps are numbered; values sit in tables; an on-page index on wide screens.

Check: read only the headings. Can you tell where each task is answered? List any heading that says
nothing ("Overview", "More").

### D3 Specific and correct examples

Definition: examples are complete, specific and consistent with the text; a reader could copy them.

- 3: Placeholder examples, fragments that cannot run, or examples that contradict the prose.
- 6: Runnable examples, but generic names or missing one step (an import, a config line).
- 9: Every example is complete and specific, uses the same names as the prose, and shows its output.

Check: pick two examples. Name anything you would have to guess to use them.

### D4 Reading comfort

Definition: measure, type size, line spacing, code styling and contrast make long reading easy.

- 3: Lines over 100 characters, small or low-contrast text, cramped code.
- 6: Comfortable body text; side columns or code blocks are cramped or low contrast.
- 9: Body at 45 to 80 characters with generous spacing; code, tables and notes are as readable as the prose.

Check: estimate the body's characters per line at 1440 and at 390; note any text you squint at.

### D5 Navigation and wayfinding

Definition: the reader knows where they are, what is next and how to reach the rest.

- 3: No location cue, no next step; the phone view hides navigation with no way back.
- 6: A sidebar or breadcrumb, but no next-page link or a phone menu that is hard to find.
- 9: Location, an on-page index, previous and next links, and a phone menu that is obvious and reachable.

Check: from the 390 screenshot, describe how a reader reaches the next page and another section.

### D6 Voice and honesty

Definition: plain, specific sentences in a consistent voice; limits and trade-offs stated.

- 3: Hype, filler or vague claims; limits hidden.
- 6: Plain, but padded or with a few unsupported claims.
- 9: Every sentence carries information; limits, versions and caveats stated where they apply.

Check: quote the weakest sentence and the strongest. Count unsupported superlatives.
